## 首次审核结论（修复前）

基础布局与主要视觉 token 一致，但组件状态、分类控件和部分 MUI 默认值仍有偏差。当前适合作为示例草稿，尚不适合作为严格遵循 DESIGN.md 的标准模板。

本轮为审核，未修改产品代码。以下区分浏览器实测与代码检查；没有发现经验证的阻断级问题，不代表完成全部无障碍或业务验收。

依据为 [DESIGN.md](../../DESIGN.md)、[Vercel 源稿](../reference/DESIGN-vercel.md)；页面行为另参照 [页面规范](../page-standards.md)。源稿没有定义的产品行为不作为视觉违规。

## 需要修正的组件偏差

### 1. P2：错误状态被聚焦状态覆盖

影响：表单页，以及使用相同字段主题的创建弹窗。

实测：无效字段获得焦点后，标签和边框变为蓝色，辅助错误文字仍为红色。同一字段同时表达“普通聚焦”和“校验失败”，状态不统一。

位置：[主题输入样式](../../src/theme/index.ts:119)、[标签聚焦样式](../../src/theme/index.ts:123)。当前 focused 规则没有处理 error 与 focused 同时成立的情形。

建议：明确 error + focused 的优先级，标签和边框使用 error-deep；键盘焦点仍需可辨认。验证普通、hover、focus、error、error + focus、disabled 的组合。

证据：[错误表单截图](../../artifacts/design-audit/form-error.png)。

### 2. P2：卡片文字按钮出现未定义的字号与密度

影响：卡片列表的 View details。

实测：13px 字号、20px 行高、32px 高度。源稿按钮字号为 14/20；已记录的 32px 例外针对小图标按钮，不能自动推广到正文操作按钮。

位置：[卡片操作](../../src/features/CardListStandardPage.tsx:64)、[small 按钮配置](../../src/theme/index.ts:106)。sizeSmall 只改高度，仍继承 MUI 的 13px 默认字号。

建议：使用标准文字按钮，或先明确登记紧凑文字按钮的适用范围，并将其字体显式映射到源稿 token。

### 3. P2：两级分类没有消费已有 category 变体

影响：表格列表与卡片列表的一、二级分类。

实测：分类按钮圆角 6px、水平内边距 6px；已有 category 变体定义的是 64px 圆角、16px 水平内边距。页面使用 contained / outlined，导致分类与普通操作按钮形态相同。

位置：[表格分类](../../src/features/TableStandardExample.tsx:74)、[卡片分类](../../src/features/CardListStandardPage.tsx:36)、[已有 category 变体](../../src/theme/index.ts:112)。

建议：复用 category 变体，并在共享主题中定义选中状态；保留当前 aria-pressed 和父子分类交互。

### 4. P2：状态徽章缺少规定的 soft 底色

影响：四页中的 StatusBadge。

实测：语义文字使用 deep 色，但背景被统一固定为白色。DESIGN.md 要求状态徽章使用 deep 前景与 soft 背景；普通标签不受此问题影响。

位置：[StatusBadge](../../src/shared/ui.tsx:85)。

建议：按状态映射 deep / soft 组合，在共享组件集中实现。当前问题属于视觉契约偏差，不是已证实的文字对比度失败。

### 5. P2：DataGrid 的局部默认值尚未纳入设计系统

影响：表格列表。

实测：表头与单元格水平内边距仍为 MUI X 默认的 10px，不在源稿间距阶梯内。现有 MuiTableCell 的 12px / 16px 配置不会作用到 DataGrid。

位置：[DataTable 表头与单元格](../../src/shared/DataTable.tsx:14)、[普通 TableCell 配置](../../src/theme/index.ts:154)。

建议：在 DataTable 显式统一单元格和表头内边距；同时复核分页 Select 的尺寸与字体，因为当前 MuiTablePagination 只覆盖部分文字样式。分页尺寸应先确定是否为已登记的密度例外，避免直接将所有内部输入强制拉高。

### 6. P2：合法长度的卡片内容会破坏网格节奏

影响：卡片列表。

压力实测：以 116 字符标题、500 字符说明替换首张卡片文本，均在 schema 允许范围内。标题扩为 6 行、说明扩为 16 行，卡片从约 331px 增至 731px，同一网格行的其他卡片被拉高并出现大量空白。

位置：[标题和说明](../../src/features/CardListStandardPage.tsx:59)。当前仅设置 overflowWrap 与说明 minHeight，没有限制行数。页面规范要求标题最多两行，摘要两至三行。

建议：标题、摘要分别截断；通过详情页保留完整内容，并验证长连续字符串。此项使用 DOM 文本压力注入验证布局，没有修改种子数据或浏览器存储。

证据：[长内容截图](../../artifacts/design-audit/cards-long-text.png)。

### 7. P2：分类信息在不同组件中表达不一致

影响：表格预览弹窗、卡片列表。

实测：表格单元格和详情页显示父级 / 子级；预览弹窗却显示原始 ID campaigns；卡片只显示 Campaigns，丢失父级路径。

位置：[预览分类](../../src/features/TableStandardExample.tsx:115)、[卡片分类](../../src/features/CardListStandardPage.tsx:61)。

建议：统一输出可读的父子分类路径；长路径允许换行或截断，并保留完整名称。

证据：[预览截图](../../artifacts/design-audit/table-preview.png)。

## 页面状态缺口

### 8. P2：详情不存在时仍展示请求重试

实测：访问 `/page-standards/detail?id=missing-resource`，页面显示 Resource not found 和 Retry。资源不存在不是可以靠重复请求恢复的普通错误，且缺少明确的返回列表操作。

位置：[详情异步状态](../../src/features/DetailStandardPage.tsx:24)、[示例服务](../../src/domain/page-standard-example.ts:34)。

建议：区分不存在与请求失败；不存在时提供返回列表，请求失败时提供 Retry。

证据：[不存在状态](../../artifacts/design-audit/detail-missing.png)。

### 9. P2：详情主信息与关联列表共用失败边界

代码检查：主记录与关联查询被合并进同一个 useAsync。关联列表请求失败时，即使主记录已读取成功，Overview 仍无法显示。关联区域也没有独立的加载、失败和重试状态。

位置：[详情查询](../../src/features/DetailStandardPage.tsx:14)、[关联区域](../../src/features/DetailStandardPage.tsx:35)。

建议：主记录成功后独立加载关联信息，关联失败仅影响关联区。此项为代码结构确认；本轮未通过网络故障注入复现，当前内存 list 服务正常路径不会抛错。

### 10. P3：卡片集合为空与筛选无结果使用相同提示

位置：[卡片空状态](../../src/features/CardListStandardPage.tsx:53)。

代码检查：两种情况均提示调整搜索或清除筛选。首次无数据时该提示没有帮助；页头已有创建入口，因此不是无法创建的问题。

建议：空集合提示创建，筛选无结果提示清除筛选，并在空状态附近提供对应操作。
