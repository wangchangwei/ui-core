# Scenario Management 卡片列表模板

## 用途

适用于可按类别浏览、可搜索、记录间存在子流程关系的运营目录。页面让管理员快速扫描场景名称和说明，检查关联流程与可见状态，并从一个紧凑的目录入口创建、复制、导入或删除场景。

这是 Forma 的完整参考页，也可作为后续资源目录或工作流模板页面的样板。当前界面语言为英文，本文档用中文说明复用要求。演示数据为本地模拟数据。

## 参考图结构分析

提供的图片呈现了从上到下四个清晰层级：

1. 页面标题和说明在左，导入、分类管理、创建操作在右。
2. 一排带总数的类别胶囊，当前类别用深色底突出。
3. 搜索框、Cards/Graph 视图开关和排序，构成同一工具栏。
4. 多列卡片目录；每张卡按场景图标、标题、描述、子流程、更新时间组织，右上角放预览/可见状态与更多操作，底部放分类。分页与每页条数位于内容底部。

卡片数目多，单卡信息精简。颜色集中在类别/子流程入口和可见状态；长标题与描述限制行数，以保持同一行卡片高度接近。参考图的多色渐变图标属于其产品视觉；Forma 页面沿用 Geist/Vercel 源稿，仅使用已登记的蓝、黑、灰和圆角变量。

## 页面顺序与行为

页面位于登录后的工作区路由 `/scenarios`，复用 AppShell 的导航、顶栏和响应式桌面提示。所有后台业务页面共用 `PageLayout`，填满侧栏之外的工作区，左右各留 32px 内距；列表、表单和详情使用相同的页头和外层内容宽度。

- 类别：All + `SCENARIO_CATEGORIES`。数字来自完整目录；一个场景可以同时属于多个类别，因此各类别数字相加可大于 All。切换类别回第一页。
- 搜索：同时查找名称和说明，输入改变后回第一页；筛选在模拟服务层执行。
- 视图：Cards 展示场景摘要；Graph 仍使用同一条筛选结果，并在卡片下方按实际子流程名称展示父场景到子流程的连接。
- 排序：按更新时间新到旧/旧到新切换。更新后场景移至排序后的对应位置。
- 分页：默认每页 12 条，支持 12、24、48；显示当前范围及上一页/下一页状态。
- 预览：打开场景说明和完整子流程列表。
- 可见状态：眼睛按钮在 visible/hidden 之间切换，操作后即时更新并保存；Viewer 只读。
- 更多：复制会新增一个名称带 `copy` 的场景；删除必须通过确认对话框。
- Create：新建场景名、说明、一个或多个类别和子流程列表，初始状态为 visible。名称和分类必填。逗号分隔的子流程在提交时解析，输入过程中保留原文。
- Import：接收 JSON 数组，单次最多 100 条。服务端逐条校验完整数组后再写入，任何一条错误都会拒绝整个文件。
- Categories：显示可用类别及其全量记录数。类别值在本模板的类型和 schema 中注册；不要在卡片页内临时造标签。
- 状态：初次加载、服务错误/重试、零结果、提交错误、导入错误、菜单/对话框、Viewer 只读都必须可以识别。

Admin 拥有完整读写权限；Viewer 可以浏览和筛选，但不能创建、导入、复制、更改可见状态或删除。路由保护与服务 API 都检查 `scenarios:read` / `scenarios:write`。

## 视觉规范

| 元素 | 约定 |
| --- | --- |
| 页面标题/说明 | 使用共享 `PageLayout` 32px 标题、14/20 正文和标题下方细分隔线 |
| 页头操作 | 右对齐：Import（次要）、Categories（次要）、Create（主操作） |
| 类别 | 使用现有 `category` pill 组件尺寸/圆角；选中用 ink/白字，非选中用白底和 hairline |
| 工具栏 | 搜索在左，结果数、两项单选视图开关和排序在右；按控件底边对齐，标签用共享主题固定上方标签，搜索有内容时显示清除操作，清除后焦点回到输入框 |
| 卡片网格 | CSS Grid 自适应 `minmax(264px, 1fr)`；4px 间距基准中的 gap 16px；桌面基准 1440px，允许大屏 5 列 |
| 卡片 | 白底、hairline 单边框、12px 圆角、24px 内边距；不加双重阴影 |
| 卡片层级 | 全宽标题可直接打开预览，标题和说明最多两行；子流程入口与状态/更多操作同行；底部时钟图标、相对时间和一枚类别 Badge；避免重复装饰图标稀释标题 |
| 颜色 | 只用主题语义色。活动/链接用源稿蓝；文案用 ink/body/mute；不要为不同卡片随机生成彩色头像或新渐变 |
| 流程视图 | 卡片标题为父场景，分隔线下方竖向展示真实子流程，名称允许换行；不可用没有领域数据支撑的假节点图或强行挤在一行的连接 |
| 分页 | 细分隔线划分内容与分页；结果范围在左，每页数量、上一页/下一页在右，每个控件只显示一处标签 |
| 浮层 | 菜单、预览、分类、新建和删除确认沿用 MUI 主题边界、焦点、Esc 和焦点恢复行为 |
| 大屏布局 | 与其他后台业务页面一致，利用侧栏之外的可用工作区；保留 232px 导航和左右 32px 内容边距，页面不得产生横向滚动 |

不得在 `src/features` 添加原生 CSS 文件、颜色/字号/间距/圆角/阴影常量或直接 localStorage 访问。单次操作复用现成领域 schema、API、AsyncState、PageLayout 和主题；新的领域字段先改 `domain/types.ts`、`schemas.ts`、`api.ts` 和持久化 seed。

## 复用步骤

1. 定义一个独立领域类型和输入 schema，明确类别、状态、关系及名称/说明边界。
2. 为异步模拟服务增加筛选、排序、分页、计数和读写权限检查。页面只调用 API，不读 seed 或 storage。
3. 用统一 `PageLayout`、类别切换、搜索、排序/视图控制和 CSS Grid 组合目录。筛选变化时回第一页。
4. 让卡片摘要只展示决策所需信息；完整关系放进预览/图视图。
5. 按权限展示操作并防重复提交；破坏性删除要有确认。失败时反馈并允许重试。
6. 验证桌面 1280/1440/1920；检查宽度、卡片行、加载/空/错误、键盘和弹窗焦点。

## 导入格式

```json
[
  {
    "name": "Manager onboarding",
    "description": "Prepare a new manager for a teammate's first week.",
    "categoryIds": ["onboarding", "customized"],
    "subflows": ["Account setup", "First-week check-in"],
    "visibility": "visible"
  }
]
```

`name` 1–120 字符，`description` 最多 500 字符，`categoryIds` 至少一个且不重复，子流程名各 1–80 字符且最多 20 条，`visibility` 为 `visible` 或 `hidden`。导入文件不提供 ID 和更新时间；模拟服务为每条记录生成唯一 ID 和时间。
